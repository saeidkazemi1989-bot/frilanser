# فریلنس‌یار آرنا (frilanser)

## 📦 نسخه‌ی آماده‌ی ویندوز (بدون نیاز به پایتون)

چهار خروجی آماده در `dist/` وجود دارد — هرکدام را راحت‌تر هستید انتخاب کنید:

| فایل | روش | برای چه کسی |
|---|---|---|
| `dist/Frilanser-Setup.exe` | **نصب‌کننده‌ی واقعی**: دوبار کلیک → نصب در Program Files + میان‌بر در منوی استارت (و در صورت انتخاب، دسکتاپ) | استفاده‌ی همیشگی روی یک سیستم |
| `dist/frilanser-portable.zip` | **پرتابل**: از حالت فشرده خارج کنید و `frilanser-gui.exe` یا `start-gui.bat` را اجرا کنید | اجرا از فلش/پوشه، بدون نصب |
| `dist/frilanser-gui.exe` | **رابط گرافیکی مستقل**: دوبار کلیک → پنجره‌ای با دکمه‌های فارسی (اجرای کامل، داشبورد، خروجی‌ها) | کسی که خط فرمان نمی‌خواهد |
| `dist/frilanser.exe` | **خط فرمان (CLI)**: فقط از CMD/PowerShell اجرا می‌شود | کاربر حرفه‌ای / اسکریپت |

> نکته‌ی مهم: `frilanser.exe` (نسخه‌ی خط فرمان) با دوبار کلیک پنجره‌ای باز می‌کند و بلافاصله
> می‌بندد چون منتظر دستور است. برای استفاده‌ی عادی **نصب‌کننده** یا **`frilanser-gui.exe`** را
> اجرا کنید. ویندوز ممکن است هشدار «ناشناس» بدهد (فایل امضا ندارد) → More info → Run anyway.

دستورهای خط فرمان (در CMD/PowerShell کنار فایل اجرایی):

```bat
frilanser.exe run              :: یک دور کامل: اسکن + غربالگری + قیمت + دمو + گزارش
frilanser.exe run --online     :: دریافت زنده از سایت‌ها (نیاز به اینترنت)
frilanser.exe serve --open     :: داشبورد وب + باز شدن خودکار مرورگر
frilanser.exe needs --full     :: کارهایی که باید خودتان انجام دهید (با متن پیشنهاد)
frilanser.exe list --verdict candidate
frilanser.exe show ponisha:760397
frilanser.exe decide ponisha:760397 approved
frilanser.exe paths            :: نمایش مسیرها (عیب‌یابی)
frilanser.exe --help
```

- اولین اجرا کنار برنامه یک `config.toml` و پوشه‌ی `data/raw` می‌سازد که قابل ویرایش‌اند
  (اگر در Program Files نصب شود، داده‌ها در `%LOCALAPPDATA%\frilanser` نوشته می‌شوند).
- نتایج (گزارش‌ها، پیش‌نمایش‌ها، وضعیت پروژه‌ها) در پوشه‌های `outbox/` و `data/` کنار برنامه نوشته می‌شوند.
- ساخت مجدد: با `scripts/build_exe.bat` روی ویندوز، یا خودکار در GitHub Actions
  (`.github/workflows/build-windows.yml`؛ هر تغییر در کد، خروجی‌ها را می‌سازد و در شاخه می‌گذارد).

## 🎨 سیستم طراحیِ داخلی (Design System)

به‌جای اینکه هر پیش‌نمایش را دستی بنویسیم، خروجی از ترکیبِ منظمِ این سه ساخته می‌شود:

```
سبک (Style)  →  پالت رنگ  →  جفت‌فونت  →  کامپوننت‌ها  →  بررسی کیفیت
```

**۱۴ سبک آماده** (با `frilanser styles` ببینید):

| سبک | مناسب برای |
|---|---|
| `soft_saas` | استارتاپ و خدمات (گرد، سایه نرم، گرادینت ملایم) |
| `glassmorphism` | طراحی مدرن با سطوح شیشه‌ای و بلور پس‌زمینه |
| `neumorphism` | سطوح برجسته‌ی نرم، بدون خطوط تند |
| `minimal` | فضای سفید زیاد، تمرکز روی محتوا |
| `brutalist` | صنعتی، حاشیه‌های ضخیم و کنتراست بالا |
| `dark_elegant` | تاریکِ شیک با درخشش ملایم |
| `luxury_gold` | طلا و جواهر و برند لوکس |
| `neon_tech` | محصولات فنی، داشبورد، هوش مصنوعی |
| `corporate` | شرکت‌ها و سازمان‌ها |
| `warm_editorial` | رستوران، کافه، محتوای فرهنگی |
| `playful` | آموزش و فروشگاه‌های شاد |
| `medical_clean` | کلینیک، درمان، آزمایشگاه |
| `ocean_trust` | املاک، مالی، بیمه |
| `rose_shop` | فروشگاه اینترنتی |

هر سبک **۱۲ پالت رنگی** و **۶ جفت‌فونت** (با fallback برای ویندوز) در اختیار دارد و
توکن‌هایش (رنگ، شعاع، سایه، حاشیه، افکت) به‌صورت متغیر CSS تزریق می‌شود.

**انتخاب سبک:** به‌طور خودکار از روی متن آگهی (مثل «طلا» → لاکچری، «کلینیک» → درمانی،
«هوش مصنوعی/داشبورد» → نئون). برای انتخاب دستی در `config.toml`:

```toml
[demo]
style = "glassmorphism"     # یا auto برای انتخاب خودکار
```

**کتابخانه‌ی کامپوننت محلی:** Hero (۳ الگو)، خدمات، آمار، کارت محصول، گام‌های همکاری،
بسته‌های قیمت، نظرات، سؤالات متداول، فرم تماس، CTA، پاورقی، پنل داشبورد.

**بررسی کیفیتِ خودکار** روی هر خروجی (در `meta.json` هم ذخیره می‌شود):
- کنتراست متن/پس‌زمینه و متنِ دکمه (حداقل ۴.۵:۱ و ۳:۱) — و اصلاح خودکار رنگ متنِ دکمه
- ریسپانسیو (viewport + قوانین `@media`)
- دسترس‌پذیری: `lang`/`dir`، حالت فوکس کیبورد، احترام به «کاهش انیمیشن»
- آفلاین بودنِ نسخه‌ی کارفرما (هیچ منبع خارجی)
- وجودِ قفل‌ها: واترمارک، لایه‌ی مسدودکننده، غیرفعال بودن فرم‌ها

> درباره‌ی ابزارهایی مثل **UI/UX Pro Max** یا **21st.dev**: آن‌ها متعلق به اکوسیستم
> Claude Code/MCP هستند و در اینجا قابل نصب نیستند (من Claude Code نیستم و دسترسی MCP
> ندارم). ضمن اینکه خروجی ما باید یک **فایل HTML آفلاینِ تک‌فایلی** باشد، بنابراین
> کامپوننت React وارد آن نمی‌شود؛ به‌جایش همان ایده را به‌صورت یک سیستم طراحی و
> کتابخانه‌ی کامپوننتِ بومی پیاده کرده‌ام. اگر پروژه‌ای با React/Next.js/Tailwind
> داشته باشید، می‌توانم خروجی را به‌صورت کامپوننت‌های React هم تولید کنم.

## ⚛️ خروجی واقعی React + Vite + Tailwind

علاوه بر پیش‌نمایش HTMLِ قفل‌شده، می‌توانید **کد واقعی و قابل اجرا** بگیرید:

```bash
frilanser react --project "کلینیک"                 # یک پروژه
frilanser react --project "طلا" --style luxury_gold  # با سبک دلخواه
frilanser react                                     # همه‌ی کاندیداها
```

سپس:

```bash
cd outbox/react/<پروژه>
npm install
npm run dev        # http://localhost:5173
npm run build      # خروجی نهایی در dist/
```

**چه چیزی ساخته می‌شود** (۲۴ فایل، همان سیستم طراحیِ HTML):

```
package.json  vite.config.js  tailwind.config.js  postcss.config.js  index.html
src/theme.js        توکن‌های طراحی (رنگ، گرادینت، شعاع، افکت‌ها)
src/content.js      همه‌ی متن‌های پروژه (فارسی، قابل ویرایش)
src/App.jsx         ترکیب صفحه
src/components/     Nav Hero HeroArt Services Stats Products Process
                    Pricing Testimonials Faq Contact Cta Footer
README.md           راهنمای اجرا
```

- پالت، فونت و شعاعِ همان سبک به `tailwind.config.js` و `src/theme.js` تزریق می‌شود
- **ریسپانسیو** (موبایل/تبلت/دسکتاپ)، **RTL** با `lang="fa" dir="rtl"`
- **دسترس‌پذیری پایه**: منوی موبایل با `aria-expanded`، برچسب‌ها و حالت فوکس
- هیچ منبع خارجی ندارد (تصویر Hero یک SVG داخلی است)
- سبک شیشه‌ای خودکار از کلاس‌های `backdrop-blur` استفاده می‌کند

> این خروجی **بر خلاف پیش‌نمایش HTML قفل نیست** چون قرار است کدِ واقعیِ شروع پروژه باشد.
> برای پیش‌نمایشی که کارفرما نتواند استفاده کند، همان `client.html` را بفرستید.

اگر می‌خواهید همراه هر `run` خودکار هم ساخته شود، در `config.toml`:

```toml
[demo]
stack = "both"      # html + react
```

> صحت این خروجی هم تست شده: پروژه‌ی تولیدشده با `npm install && npm run build`
> در CI واقعاً کامپایل شد (۴۵ ماژول، CSS ۱۱ کیلوبایت، JS ۱۵۷ کیلوبایت).

## 📱 نسخه‌ی اندروید + به‌روزرسانی از داخل برنامه

### نصب روی گوشی

۱. فایل `dist/frilanser.apk` را روی گوشی ببرید (تلگرام/کابل/کارت حافظه).
۲. روی آن بزنید و «Install» را تأیید کنید. اگر پیام **ناشر ناشناس** آمد:
   «تنظیمات → اجازه نصب برنامه‌های ناشناس → برای مرورگر/مدیر فایل» را فعال کنید.
۳. برنامه را باز کنید؛ داشبورد در خود گوشی بالا می‌آید (اینترنت روی خود دستگاه).

این نسخه با **python-for-android** ساخته می‌شود: یک وب‌سرورِ کوچکِ Flask روی
خود گوشی اجرا می‌شود و رابط برنامه در یک WebView همان صفحاتِ داشبورد است؛
پس همه‌چیز (اسکن، غربال، دمو، قیمت) همان چیزی است که روی ویندوز می‌بینید.

### 🔄 دکمه‌ی به‌روزرسانی (دیگر نیازی به دانلود دستی از گیت‌هاب نیست)

بالای داشبورد یک کارتِ «به‌روزرسانی برنامه» هست:

```
نسخه‌ی فعلی: ۱.۰.۰ — [ بررسی نسخه‌ی جدید ] [ دریافت و نصب نسخه‌ی X ]
```

گردش کار:

1. **بررسی**: برنامه یک فایل JSON ساده (مانیفست نسخه) را می‌خواند و نسخه‌ها را مقایسه می‌کند
2. **دریافت**: در صورت وجود نسخه‌ی جدید، فایل نصب دانلود می‌شود (نوار پیشرفت)
3. **بررسی امضا**: `sha256` فایل با مانیفست مقایسه می‌شود
4. **نصب**: صفحه‌ی نصب اندروید باز می‌شود (فقط یک بار اجازه‌ی «نصب برنامه‌های ناشناس» لازم است)

همین کار از خط فرمان هم ممکن است:

```bash
frilanser update --check-only     # فقط بررسی
frilanser update                  # بررسی + دانلود + نصب
frilanser update --download-only  # فقط دانلود
```

**منبعِ به‌روزرسانی**: مانیفست روی `dist/updates/manifest.json` و فایل‌ها در
یک Release به تگ `latest`. اگر بخواهید منبع را عوض کنید (مثلاً هاست شخصی خودتان):

```toml
[update]
manifest_url = "https://example.com/frilanser/manifest.json"
```

> نکته: چون منبع روی گیت‌هاب است، اگر دسترسی به آن در شبکه‌ی شما محدود باشد،
> برنامه خطا را در همان کارت نشان می‌دهد و می‌توانید آینه‌ی دلخواه را در
> `config.toml` وارد کنید.

## 📌 پیگیریِ پیشنهادها (ثبت دستی + تشخیص خودکار)

مسئله: هر بار برنامه به‌روزرسانی می‌شود، نباید پیشنهادهایی که داده‌اید گم شوند؛
و باید بفهمید کدام پروژه دیگر قابل پیگیری نیست (واگذار شده یا بسته شده).

### ثبت وضعیت

از داشبورد، صفحه‌ی هر پروژه (یا از خط فرمان):

| دکمه / فرمان | معنا |
|---|---|
| ✉️ پیشنهاد دادم | روی این آگهی پیشنهاد ثبت کردم (مبلغش را هم بنویسید) |
| 🏆 پروژه را گرفتم | کارفرما پروژه را به من سپرد |
| ↩️ نگرفتم / رد شدم | پیشنهادم پذیرفته نشد |
| 🔒 واگذار یا بسته شد | دیگر قابل پیگیری نیست |
| 🧹 پاک کردن | بازگشت به حالت عادی |

```bash
frilanser state ponisha:760397 submitted --price 7000000
frilanser state ponisha:760397 won
frilanser track                      # فهرستِ پیشنهادهای شما
```

در داشبورد هم فیلترهای «پیشنهادهای من»، «گرفتم» و «واگذار/بسته» بالای صفحه اضافه شده‌اند.

### حفظ شدن در به‌روزرسانی‌ها

وضعیتِ هر پروژه در فایل داده‌ها (`data/projects.json`) ذخیره می‌شود و اسکنِ بعدی
فقط متن و قیمتِ آگهی را به‌روز می‌کند — **وضعیت، مبلغ پیشنهادی شما و تاریخچه دست‌نخورده می‌ماند**.

### تشخیصِ خودکارِ «واگذار شد»

دو راه دارد:
- **نشانه‌ی متنی**: اگر در متن آگهی عبارت‌هایی مثل «واگذار شد»، «بسته شد»، «منقضی»،
  «لغو شد» بیاید (نشانه‌های مبهم مثل «تکمیل شد» فقط در انتهای جمله پذیرفته می‌شوند تا
  با «تکمیل فایل اکسل» اشتباه گرفته نشود).
- **حذف از فهرست**: اگر پروژه‌ای که پیشنهاد داده‌اید **دو بار پیاپی** در اسکن دیده نشود،
  «احتمالاً واگذار یا بسته‌شده» علامت می‌خورد و در گزارش می‌آید.

وضعیت‌های دستی («گرفتم» / «نگرفتم») هرگز به‌طور خودکار تغییر نمی‌کنند.

## 🌱 حالتِ تازه‌کار (مبالغ رقابتی‌تر)

اگر تازه وارد این کار شده‌اید، رقابت با با‌سابقه‌ها سخت است؛ برای همین برنامه
برای هر آگهی **احتمال اینکه کارفرما آن را به یک تازه‌کار بسپارد** را از ۱۰۰ حساب می‌کند:

- **رقابت**: هرچه تعداد پیشنهادهای رسیده کمتر باشد، شانس شما بیشتر (کمتر از ۴ پیشنهاد عالی است)
- **اندازه‌ی کار**: پروژه‌های کوچک‌تر (زیر ۶ ساعت) راحت‌تر به تازه‌کار سپرده می‌شوند
- **لحنِ آگهی**: «تازه‌کار هم باشد اشکالی ندارد»، «قیمت مناسب مهم است»، «ساده و فوری» → مثبت؛
  «حداقل ۵ سال سابقه»، «نمونه‌کار الزامی»، «تیم حرفه‌ای» → منفی
- **بودجه**: مبالغ خیلی بالا حرفه‌ای‌ها را جذب می‌کند
- **تازگیِ آگهی**: آگهی‌های امروز هنوز شانس دارند

در داشبورد نشانِ 🌱 با امتیاز می‌بینید، فیلترِ **«مناسب تازه‌کار»** آن‌ها را بالا می‌آورد،
و در صفحه‌ی هر پروژه دلیلِ امتیاز و توصیه‌ی عملی نوشته شده است.

### تخفیفِ ورود به بازار

با روشن بودنِ `newcomer_mode`، قیمت پیشنهادی برای این پروژه‌ها پایین‌تر بسته می‌شود:

```toml
[pricing]
newcomer_mode = true
newcomer_discount_high   = 0.15   # شانس بالا
newcomer_discount_medium = 0.10
newcomer_discount_low    = 0.05
newcomer_floor_share     = 0.85   # سقف تخفیف: از ۸۵٪ کفِ مبلغ پایین‌تر نرود
```

تخفیف **روی قیمت نهایی** اعمال می‌شود (بعد از مقایسه با بودجه‌ی کارفرما) تا قیمت
همچنان با بودجه هم‌خوان بماند. در متنِ پیشنهاد هم توصیه‌هایی برای جبرانِ سابقه‌ی کم می‌آید
(ارسال دمو، پیشنهادِ فاز‌بندی‌شده، تأکید بر زمان تحویل).

> اگر نخواستید، کافی است `newcomer_mode = false` کنید تا قیمت‌ها به حالت قبل برگردد.

## 🩺 برنامه اجرا می‌شود اما داده نمی‌آورد؟

اولین کاری که برنامه می‌کند: اگر پایگاه داده خالی باشد، **خودکار اسکن را شروع می‌کند**
و خلاصه می‌دهد: «۴۰ آگهی، ۱۰ کاندیدا، ۶ پیش‌نمایش ساخته شد».

اگر باز هم چیزی نیامد، دکمه‌ی **«عیب‌یابی»** (یا `frilanser.exe doctor`) را بزنید.
این دستور پنج چیز را بررسی می‌کند و نسخه‌ای از گزارش را در `outbox/doctor.txt` می‌گذارد:

1. محیط اجرا: exe است؟ کجا نصب شده؟ پوشه‌ی داده‌ها کجاست؟ **قابل نوشتن هست؟**
2. اسنپ‌شات‌های آفلاین (`data/raw`): اگر نباشند، از داخل برنامه بازیابی می‌شوند
3. وضعیت داده‌ها: چند آگهی دارید و چند کاندیدا/پیش‌نمایش
4. **دسترسی به تک‌تک سایت‌ها** با علت دقیق (DNS، SSL، timeout، خطای HTTP)
5. پیشنهادِ دقیقِ قدمِ بعد

رایج‌ترین دلیلِ «هیچ داده‌ای نمی‌آید»: **سایت‌های ایرانی روی شبکه‌ی شما بسته‌اند**
(مثلاً خارج از ایران بدون VPN). در این حالت برنامه به‌طور خودکار از
**اسنپ‌شات‌های داخلی** استفاده می‌کند و ۴۰ آگهی واقعی را نشان می‌دهد؛
برای داده‌ی کاملاً تازه، یکی از این دو کار را بکنید:

- با VPN/فیلترشکن وصل شوید و «دریافت زنده از سایت‌ها» را بزنید، یا
- صفحه/فایل خام هر سایت را در پوشه‌ی `data/raw` بگذارید (مثل `ponisha-1403-01-01.json`)

> نکته: نسخه‌ی خط فرمان هم همین کار را می‌کند: `frilanser.exe doctor`
> (با `--offline` بررسی اینترنت را رد می‌کند).

## 🖼 پیش‌نمایش گرافیکی (دمو) برای هر پروژه

برای هر پروژه‌ی کاندید یک **طرح گرافیکیِ واقعی** از خروجی ساخته می‌شود (نه یک متن کلی).
نوع طرح از روی عنوان/توضیح آگهی تشخیص داده می‌شود:

| تشخیص داده‌شده از آگهی | پیش‌نمایش ساخته‌شده |
|---|---|
| «طراحی وب‌سایت کلینیک…» | سایت کامل کلینیک: هدر، نوبت‌دهی آنلاین، خدمات، پزشکان، تماس |
| «طراحی وبسایت شرکت تجهیزات پزشکی» | سایت شرکتی با کاتالوگ تجهیزات، گواهی‌نامه‌ها، فرم استعلام |
| «طراحی دو سایت فروشگاهی طلا» | فروشگاه طلا با قیمت لحظه‌ای، کارت محصول، سبد خرید |
| «افزودن زبان انگلیسی به سایت فروشگاهی» | همان فروشگاه با نمایش نسخه‌ی انگلیسی و تغییر زبان |
| «یکپارچه‌سازی Odoo» / «وب‌اپلیکیشن پژوهشی» | صفحات واقعی پنل: داشبورد، نمودار، جدول، وضعیت |
| «استخراج محتوای ۱۵۰ کتاب» | صف پردازش، پیشرفت، نتایج و نمونه‌ی خروجی JSON |

هر پیش‌نمایش در دو نسخه ساخته می‌شود:

- `index.html` — **نسخه‌ی داخلی**: همراه امتیاز اجراپذیری، برآورد ساعت، لینک آگهی (برای شما)
- `client.html` — **نسخه‌ی ارسال به کارفرما**: فقط طرح + مبلغ و زمان تحویل؛
  بدون امتیاز/برآورد داخلی و بدون لینک آگهی

**کارفرما می‌بیند اما نمی‌تواند استفاده کند:**

- واترمارک موربِ سراسری روی کل صفحه (برای عکس گرفتن یا استفاده هم به‌درد نمی‌خورد)
- لایه‌ی شفاف روی همه چیز: هر کلیک پیام «این فقط پیش‌نمایش است؛ نسخه‌ی قابل استفاده پس از
  تایید قرارداد تحویل می‌شود» را نشان می‌دهد
- همه‌ی فرم‌ها و دکمه‌ها غیرفعال، لینک‌ها بی‌اثر، انتخاب متن و راست‌کلیک و
  کلیدهای Ctrl+S / Ctrl+U / Ctrl+P / Ctrl+C قفل
- هیچ تصویر یا دارایی خارجی ندارد (فایل تکی و آفلاین) و برای موتورهای جستجو `noindex` است

---

اپی که **سایت‌های فریلنسری ایرانی را می‌گردد**، آگهی‌ها را از نظر
**«آیا این کار را می‌شود در آرنا انجام داد؟»** غربال می‌کند، برای گزینه‌های خوب
**دموی واقعی** و **قیمت پیشنهادی** می‌سازد، و هرجا که لازم باشد **شما وارد شوید**
(ثبت پیشنهاد در سایت، گرفتن دسترسی، تحویل پروژه) به شما اطلاع می‌دهد.

> تقسیم کار: **پیدا کردن + غربال کردن + ساخت دمو + قیمت‌گذاری + اجرا و آماده‌سازی خروجی = خودکار
> ثبت پیشنهاد در سایت فریلنسری و تحویل نهایی = با شما** (برای هر کدام متن/فایل آماده تحویل داده می‌شود)

---

## ۱. نصب و اجرا

```bash
git clone <این ریپو> && cd frilanser

# نصب وابستگی‌ها (دو راه)
./scripts/setup.sh                        # نصب در .pylib داخل پروژه (توصیه‌شده)
# یا: pip install -r requirements.txt

# اجرای کامل یک دور خط لوله (بدون اینترنت، از روی اسنپ‌شات‌های موجود)
python -m frilanser run

# داشبورد وب (تایید/رد، دیدن دمو، کپی متن پیشنهاد)
python -m frilanser serve              # http://localhost:5000
```

اگر پکیج‌ها را نمی‌خواهید در سیستم نصب کنید:

```bash
pip install --target .pylib -r requirements.txt
python -m frilanser run                 # مسیر .pylib خودکار اضافه می‌شود
```

> نکته: در محیط‌هایی که دسترسی به سایت‌های ایرانی مسدود است (مثل این sandbox)،
> برنامه به‌طور خودکار از **اسنپ‌شات‌های `data/raw`** استفاده می‌کند. روی سیستم
> خودتان با `--online` از سایت زنده می‌خواند.

افزودن منبع جدید: یک کلاس در `frilanser/sources/` بسازید (از `BaseSource`

در اولین اجرای `--online`، متن صفحه در `data/cache` ذخیره می‌شود؛ با کپی آن به
`data/raw/<کلید>-<تاریخ>.md` یک اسنپ‌شات آفلاین هم خواهید داشت.

## ۳. خط لوله (pipeline)

```
collect ──▶ screen ──▶ propose ──▶ demo ──▶ notify
  │           │           │          │         │
  │           │           │          │         └─ گزارش مارک‌داون + صف «نیاز به ورود شما»
  │           │           │          └─────────── دموی HTML تعاملی برای هر کاندید
  │           │           └────────────────────── قیمت، مراحل پرداخت، متن پیشنهاد
  │           └────────────────────────────────── دسته‌بندی، امتیاز اجراپذیری، زمان
  └────────────────────────────────────────────── خواندن آگهی‌ها (شبکه یا اسنپ‌شات)
```

### غربالگری: چه پروژه‌هایی «در آرنا قابل اجرا» هستند؟

* **بله (تحویل کامل):** استخراج/پردازش داده، اسکریپت و اتوماسیون، ربات/بات،
  اپلیکیشن هوش مصنوعی، وب‌سایت و وب‌اپ، لندینگ، داشبورد و گزارش‌ساز.
* **تا حدی:** افزونه/قالب وردپرس (کد تحویل می‌شود، نصب با شماست)، اپ موبایل
  (نسخه وب/PWA)، تولید محتوا و ترجمه (نیاز به بازبینی انسانی)، ورود داده.
* **خیر:** سئوی مستمر، طراحی گرافیک/لوگو/کاتالوگ، رندر و مدلسازی، تدوین و
  صدا، آموزش/تدریس/مشاوره، ادمین و پشتیبانی مستمر، سخت‌افزار و تأسیسات،
  ربات‌های معاملاتی.

امتیاز هر پروژه (۰ تا ۱۰۰) از روی این عوامل کم و زیاد می‌شود:
تناسب دسته، **تعداد رقبا**، بودجه و تناسب آن با برآورد ما، شفافیت توضیحات،
نیاز به دسترسی/نرم‌افزار لایسنس‌دار/عملیات انسانی، چندفازی بودن، و زمان اجرا.

خروجی: `candidate` (کاندیدا)، `review` (نیاز به بررسی)، `rejected` (رد شده)
— هر کدام **با دلیل فارسی**.

### قیمت‌گذاری

```
قیمت پایه = ساعت برآوردی × نرخ ساعتی × ضریب پیچیدگی
قیمت نهایی = قیمت پایه × (۱ + کمیسیون پلتفرم + حاشیه ریسک)  ← گرد شده
اگر بودجه‌ی کارفرما خیلی بیشتر از برآورد باشد → قیمت‌گذاری ارزش‌محور
اگر کمتر باشد → پیشنهاد جایگزین با محدوده‌ی کاهش‌یافته
```

همه‌ی این مقادیر در `config.toml` قابل تنظیم‌اند (نرخ ساعتی، کف قیمت، سقف ساعت، …).

## ۴. دستورها

```bash
python -m frilanser run            # یک دور کامل (collect→screen→propose→demo→report)
python -m frilanser run --online   # دریافت زنده از سایت‌ها
python -m frilanser scan --online  # فقط جمع‌آوری
python -m frilanser screen         # فقط غربالگری
python -m frilanser propose        # فقط قیمت‌گذاری
python -m frilanser demo --limit 5 # ساخت دمو برای کاندیداها
python -m frilanser report         # ساخت گزارش + صف «نیاز به ورود شما»
python -m frilanser list --verdict candidate
python -m frilanser show ponisha:760397
python -m frilanser needs --full   # کارهایی که باید خودتان انجام دهید (با متن پیشنهاد)
python -m frilanser decide ponisha:760397 approved --note "کارفرما پذیرفت"
python -m frilanser serve          # داشبورد وب
```

## ۵. گردش کارِ پیشنهادی (این همان چیزی است که خواستید)

1. **اسکن خودکار:** برنامه همه‌ی آگهی‌های جدید را می‌خواند و غربال می‌کند.
2. **دمو + قیمت برای گزینه‌های خوب:** برای هر کاندیدا یک دموی تعاملی و متن
   پیشنهادِ آماده ساخته می‌شود.
3. **اطلاع به شما:** در داشبورد (بخش «نیاز به ورود شما») و در گزارش
   `outbox/reports/YYYY-MM-DD.md` به شما گفته می‌شود چه کارهایی مانده است:
   * ثبت پیشنهاد در سایت (با متن آماده‌ی کپی‌کردن)
   * گرفتن دسترسی/اطلاعات از کارفرما
   * توافق روی شکل تحویل (مثلاً وردپرس یا سایت اختصاصی)
4. **تایید شما:** وقتی کارفرما پذیرفت، پروژه را در داشبورد «تایید» می‌کنید
   تا اجرا و آماده‌سازی خروجی شروع شود.
5. **تحویل با شما:** بعد از آماده شدن، در همان صفحه «تحویل داده شد» را می‌زنید؛
   فایل‌ها را در سایت بارگذاری می‌کنید.

## ۶. فایل‌ها

```
config.toml              تنظیمات (نرخ ساعتی، سقف زمان، منابع، …)
data/raw/                اسنپ‌شات‌های واقعی آگهی‌ها (json + متن خام برای تست پارسرها)
data/projects.json       وضعیت و تحلیل همه‌ی پروژه‌ها
data/needs_you.json      صف کارهایی که باید خودتان انجام دهید
outbox/demos/            دموهای HTML ساخته‌شده (هر کدام یک فایل مستقل)
outbox/reports/          گزارش روزانه (latest.md همیشه آخرین گزارش است)
frilanser/               کد برنامه (sources، screening، pricing، demo_builder، web)
frilanser_app.py         نقطه‌ی ورود نسخه‌ی اجرایی (EXE)
dist/frilanser.exe       فایل اجرایی ویندوز (ساخته‌شده توسط CI)
dist/ci-report.md        گزارش آخرین تست نسخه‌ی اجرایی روی ویندوز
tests/                   تست‌های خودکار
scripts/scan.sh          اجرای دوره‌ای (cron)
scripts/setup.sh         نصب وابستگی‌ها
scripts/build_exe.bat    ساخت EXE روی ویندوز
.github/workflows/       ساخت خودکار EXE روی ویندوز
```

## ۸. محدودیت‌ها

* **احترام به سایت‌ها:** بین درخواست‌ها تأخیر وجود دارد (`fetch.delay_between_requests`)
  و نتایج کش می‌شوند. پیش از اسکن گسترده، شرایط استفاده‌ی هر سایت را بخوانید.
* برنامه پیشنهاد را **برای شما آماده می‌کند**؛ ثبت آن در سایت (و احراز هویت،
  گفتگو با کارفرما، تحویل نهایی) عمداً دستی است.
* دموها با **داده‌های نمونه** ساخته می‌شوند تا خروجیِ نهایی را نشان دهند،
  نه اینکه ادعا کنند کار انجام شده است.
